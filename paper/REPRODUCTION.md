# FastCDC 论文实验复现报告

对照 `paper/atc16-paper-xia.pdf`（USENIX ATC'16）第 5 章，本项目复现了论文的分块
算法与基线，并用本地缩比 + 合成数据集跑出 Table 3 / Fig 11 / Fig 12 / Table 4-5 的
同构结果。原始数据见 `results/*.csv`，复现脚本见 `tools/run_experiments.sh`。

> 本次在本机（Windows / x86-64）以修复后的代码（见 §9.1 的 FIX-1 / FIX-2）**重跑了
> 全部实验**，下表数值均取自 `results/*.csv` 的本轮输出。算法保真度审查与后续修复项
> 见 `docs/PAPER_CONFORMANCE.md`。

## 1. 运行环境与构建

- 平台：Windows / x86-64，MSYS2 UCRT64，GCC 15.2.0 `-O3`，OpenSSL 3.5.2
  （论文为 Ubuntu 12.04 + Intel i7-4770 @3.4GHz + GCC 4.7.3）。
- 构建：`cmake -B cmake-build-release -DCMAKE_BUILD_TYPE=Release && cmake --build cmake-build-release`
  （默认 Release `-O3`；去重指纹用 OpenSSL SHA-1）。
- 运行：`./cmake-build-release/FastCDC[.exe] <path> [--recursive] [--algo fastcdc|gear|rabin|fsc]`
  `[--expected-size N] [--min-size N] [--nc-level 1|2|3|--nc|--no-nc] [--runs N] [--csv P]`。
- 一键复现：`tools/run_experiments.sh`（Windows 下自动回退到 `FastCDC.exe`）。

## 8. 结论

- **趋势层面：已复现。** 期望块长、MinSize、NC level 三条主线的方向与论文一致；
  “FC-NC-Min4KB 去重最高”“切点跳过提速但降去重”“NC-2 甜点”“XC 最低”等关键结论均成立。
- **数值层面：未复现（也无法 1:1 复现）。** 论文绝对数值依赖其未公开的 Gear 随机表、
  大规模真实数据集（约 5TB）与不同 CPU，本项目为缩比数据 + 自生成 Gear 表 + GCC/Windows。

## 9. 与论文差异的来源（需在论文/答辩中说明）

1. **Gear 随机表未公开**：本项目自生成，块边界位置与论文不同，去重率与平均块长有系统偏差。
2. **数据集缩比**：LNX 用 5 个 emacs 版本（论文 260 个 Linux 版本、105GB），去重率量级
   （32% vs 97%）不可比；TAR 用 0.65GB（论文 19GB）。
3. **CPU/编译器/OS**：Windows + GCC 15.2.0 vs Linux + Intel i7 + GCC 4.7，绝对速度不可比，
   只能看相对倍数。
4. **NC level 1/3 掩码**：论文只公开 level 2 的 11/13/15 位掩码；level 1/3 按论文的
   位对 (14,12)/(16,10) 在同分布上生成，属假设。
5. **合成 SYN 不含边界偏移**：导致 XC 在该集上异常好；真实 SYN 不成立。
6. **去重粒度为精确去重**：SHA-1 摘要 + 逐字节确认，等价于精确去重；论文亦用 SHA-1。

### 9.1 本轮算法保真度修正（FIX-1 / FIX-2）

依据 `docs/PAPER_CONFORMANCE.md` 的审查，本轮修复了两处会改变复现数值的缺陷：

- **FIX-1（Rabin 除数随期望块长缩放）**：此前 `D` 固定为 `0x2000`（对应 8KB），
  导致 `--expected-size 4K/16K` 仍以 8KB 为目标，RC 平均块长几乎不随期望块长变化。
  现令 `D = expectedSize`（论文 §2 Eq.1：D 即平均块长；§5.1：max/min 随期望块长缩放）。
  效果：TAR 的 RC 平均块长由近乎恒定改为 **5406 / 10879 / 21893**（4K/8K/16K），
  呈缩放关系，趋势对齐论文（5561 / 11873 / 24067）。
- **FIX-2（NC 归一化切换点随 MinSize 调整）**：此前 `NormalSize` 恒为 `expectedSize`，
  当 `--min-size 8192 --nc-level 1|2|3` 时 `MinSize == NormalSize`，`MaskS` 永不参与、
  NC 退化为单一 `MaskL`。现 NC 开启时取 `NormalSize = max(expected, MinSize + expected/2)`
  （`Min4KB → 8KB`、`Min8KB → 12KB`，与论文 §5.4「归一化块长 = 4KB + 最小块长」一致）。
  效果：TAR 的 `FC-NC-Min8K` 平均块长由 **10420 → 14015**，接近论文 Table 5（~14076）；
  `Min4K` 数值不变（`NormalSize` 仍为 8KB）。
- **回归基线**：非 NC 路径（`--no-nc`、`min=2KB`）与 `Min4K` 的 NC 结果未受影响，
  已核对与修复前一致。

`NormalSize` 公式对 `Min2KB` 的处理（`min + expected/2 = 6KB < 8KB`，取 8KB）是为同时
满足 Algorithm 1 示例与 §5.4 表述的最小改动，详见 `docs/PAPER_CONFORMANCE.md` §5。
